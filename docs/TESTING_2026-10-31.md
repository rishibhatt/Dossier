# How to test everything changed on 30–31 Oct 2026

Work top to bottom. Each step says what to do and what you should see. Steps marked **LIVE** need the deployed site; everything else runs on `npm run dev` (http://localhost:3000).

## 0. One-time setup

1. **Supabase → Authentication → URL Configuration**
   - Site URL: `https://dossier-cv.com` (leave as is).
   - Redirect URLs: add `http://localhost:3000/**` and `http://localhost:3001/**` (keep `https://dossier-cv.com/**`).
   - Why: Supabase only sends people back to addresses on this list. Anything else falls back to the Site URL, which is why localhost logins landed on dossier-cv.com.
2. **Supabase → SQL editor:** run `supabase/migrations/20261030120000_admin_segments.sql`, then `supabase/migrations/20261031120000_billing_views_email.sql`, then `supabase/migrations/20261101120000_portfolio_writes_server_only.sql`. All three must succeed before the app is used (local or live).
3. **`.env.local`** (local only; never commit):
   ```
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   RAZORPAY_KEY_ID=rzp_test_...
   RAZORPAY_KEY_SECRET=...
   RAZORPAY_WEBHOOK_SECRET=any-long-random-string
   CRON_SECRET=another-long-random-string
   BREVO_API_KEY=...
   BREVO_SENDER_EMAIL=hello@dossier-cv.com
   ```
   Netlify (production) gets the same names but `NEXT_PUBLIC_SITE_URL=https://dossier-cv.com`.
4. Restart `npm run dev` after changing env files.

> Local and live share one Supabase database. Anything you create on localhost is marked as test data automatically (step 3), but it is real data. A separate Supabase project for development is the clean fix later.

## 1. Login stays on localhost

1. Open http://localhost:3000/login → **Continue with Google** → you return to `http://localhost:3000/dashboard` (not dossier-cv.com).
2. Sign out → http://localhost:3000/signup with a new email → open the confirmation email → the link opens `http://localhost:3000/auth/callback...` and lands on the dashboard.
3. http://localhost:3000/forgot-password → reset email link opens localhost.
4. **LIVE:** repeat 1 on https://dossier-cv.com → you stay on dossier-cv.com.
   - Still landing on dossier-cv.com locally? The localhost URL is missing from Supabase Redirect URLs (step 0.1), or the dev server runs on a port you did not add.

## 2. Test data stays out of analytics and admin

1. On localhost open DevTools → Network, filter `google|clarity|posthog`, click around → **no requests**.
2. Your localhost account from step 1 → Supabase → Table editor → `users` → `is_test = true`.
3. **LIVE:** visit `https://dossier-cv.com/?notrack=1` once → DevTools → Application → Local storage has `dossier_notrack = 1` → no analytics requests on any page. `?notrack=0` turns it back on.
4. **LIVE (another browser, not opted out):** tap or scroll with the mouse wheel → requests to `googletagmanager`, `clarity.ms` and `i.posthog.com` appear. PostHog → Activity shows your pageview within a minute.
5. Clarity → Settings → Setup → turn **Bot detection** on. PostHog → Project settings → add filter `$host does not contain localhost`.

## 3. Admin console

Open the admin site (admin.dossier-cv.com, or http://localhost:3000/admin in dev) and sign in with your authenticator code.

1. **Overview:** click 7 / 30 / 90 / 180 / 1 year → numbers and charts change. "Include test accounts (N)" → numbers go up; "Hide test accounts" → back.
2. "Activation, joined in N days" shows signed up → saved a resume → published → paying, with percentages.
3. **Users:** filter Accounts = Test only → your localhost accounts. Real only (default) hides them. Try Joined = last 7 days and Order = Oldest first.
4. Open a real user → **Mark as test** → they disappear from Overview numbers. **Mark as real** → back. `/admin/audit` shows both actions.

## 4. Payments (Razorpay test mode, no money moves)

1. Sign in as a normal (non-admin) test user → Dashboard → **Plan & billing**.
2. Cards show prices; in India the buttons say ₹, elsewhere $. "Pay in … instead" switches currency.
3. **Get Starter** → Razorpay popup → Netbanking → any bank → **Success** (or card `4100 2800 0000 1007`, OTP any 4–10 digits) → toast "Starter is on" → page shows Starter as current plan.
4. Check: Supabase `subscriptions` has a row (`product = starter`, `status = active`); `/admin` → Latest subscriptions shows it; a receipt email arrives.
5. **Pro for a month** → card `4100 2800 0000 1007`, any future date, any CVV → plan shows Pro "paid until" ~30 days. Buy **Pro for a year** → date moves ~365 days further (stacking).
6. Failure: try UPI `failure@razorpay` → error toast, plan unchanged.
7. **Webhook** (needs a public URL): Razorpay → Webhooks → add `https://dossier-cv.com/api/billing/webhook` (or an ngrok URL to your localhost) with your secret and events `order.paid, payment.captured, payment.failed, refund.processed, payment.dispute.lost`. Make a test payment → delivery shows **200**. Supabase `payment_events` has the event with `processed_at` set.
8. **Refund:** Razorpay → Payments → the Pro-month payment → Refund full → within a minute Pro end date moves back 30 days. Refund all Pro payments → plan falls back to Starter (you own it). Refund Starter → Free.
9. Wrong key test: in `.env.local` change `RAZORPAY_WEBHOOK_SECRET`, send a test webhook → **400 bad signature**, nothing changes. Put it back.

## 5. Festival offers

1. Diwali (30% off, rupee buyers) runs 1–11 Nov 2026. On or after 1 Nov with an Indian time zone: a dark bar at the top of every marketing page with a live countdown; billing buttons show the old price struck through.
2. To test before then, temporarily change the Diwali `starts` in `src/lib/billing/pricing.ts` to yesterday, reload, check the bar and ₹279 / ₹1,049 / ₹209 prices, buy once in test mode (amount in Razorpay matches), then **undo the edit**.
3. Close the bar with × → it stays hidden on reload.

## 6. Emails

1. Brevo → Senders, Domains: `dossier-cv.com` shows **Authenticated**; `hello@dossier-cv.com` is a verified sender.
2. Admin → Overview → **Email me one copy of every app email** → 10 emails marked `[TEST]` arrive.
3. Open one in Gmail → ⋮ → **Show original** → `SPF: PASS`, `DKIM: PASS` (dossier-cv.com), `DMARC: PASS`, From `hello@dossier-cv.com`.
4. Send one to the address shown at https://www.mail-tester.com → score 9/10 or better.
5. Send a mail from your Gmail to `hello@dossier-cv.com` → it arrives in that inbox (Brevo only sends; the mailbox is separate).
6. **Unsubscribe:** in a product email (not a receipt) click "Stop these emails" → a confirm page opens (nothing changed yet) → press **Stop these emails** → Dashboard → Settings → both Email boxes are unticked. Tick them again and Save.
7. **Daily job by hand** (Git Bash):
   ```bash
   curl -H "Authorization: Bearer YOUR_CRON_SECRET" http://localhost:3000/api/cron/emails
   ```
   → `{"picked":N,"sent":N}`. Wrong secret → `401`. Test accounts never receive these.
8. **LIVE:** Netlify → Functions → `daily-emails` shows a run each day at 04:30 UTC.

## 7. Visit counter and sharing

1. Publish a portfolio with your test user, copy its `/p/...` link.
2. Open the link in a **private window** (not signed in), then tap or use the mouse wheel → Supabase `portfolio_views` gets `views = 1` for today. Reload and tap again → still 1 (one per browser per day).
3. Open it while signed in as the owner → count does not change.
4. Dashboard → the site shows "1 visits in 7 days". On Pro, a 14-day bar chart and a 30-day total appear; on Free, a "Pro shows visits day by day" link.
5. **Share on LinkedIn** and **Send on WhatsApp** open with the site link filled in.
6. First publish ever for an account → the "Your site is live" share-kit email arrives.

## Security fixes to spot-check

1. Publishing still works (publish, edit, republish) after the third migration.
2. Direct write is blocked: in the browser console on the site, signed in, `supabase.from('published_portfolios').insert(...)` through the REST API returns `permission denied`.
3. Webhook: a stored event id replayed returns 200 `duplicate`; any other database error returns 500 so Razorpay retries.
